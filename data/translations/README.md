# Quiz translations

`ab/` preserves the original complete English and Simplified Chinese translation
batches used by the archival A/B builder. `multibank/` contains shared strings
for the optional multi-bank bundle. The files use the same source-text SHA-256 as `content_texts` in
SQLite, so identical Italian wording across banks is translated only once.

`multibank/reused_ab.jsonl` records existing translations with
`origin="existing_ab"`. `multibank/batch_NNN.jsonl` records new translations made
by lower-cost worker models; `origin` names the model, e.g. `"gpt-6.1-terra"`. Every row has `id`,
`it`, `en`, `zh` and `origin`. `zh` means Simplified Chinese (`zh-Hans` in SQLite).
New text starts as `review_status="draft"`. After an independent GPT-6.1 Terra
semantic review of both target languages, verified rows use `review_status="reviewed"`.
Reviewer model, agent, date and a SHA-256 of the exact Italian/English/Chinese
wording are recorded on each reviewed row. Existing A/B translations remain
`existing`; this review pass does not imply a new review of that inherited text.

`tasks/NNN.jsonl` is the ignored, generated matching ordered source batch, including question/group
references. It is an input work queue, not translated output. A batch is complete
only when all IDs appear exactly once and each has both target languages.

```sh
python3 scripts/check_bank_translations.py
python3 scripts/check_bank_translations.py --require-complete
python3 scripts/check_bank_translations.py --require-complete --require-reviewed
python3 scripts/build_database.py --require-translations
python3 scripts/build_database.py --require-translations --require-reviewed
python3 scripts/export_quiz.py
```

The checker validates complete task membership, unique IDs, unchanged Italian,
nonempty target text and model origin. The builder additionally checks source
hashes and rejects conflicting translations of the same string. Review checks
require per-batch evidence and reject changed wording with a stale reviewed
marker. `reviews/translation-review/batch_NNN.json` lists every verified ID,
correction with before/after wording and reason, and any unresolved entries.
`baseline-manifest.json` records the draft file hashes at the start of this pass.
`summary.json` summarizes the completed review. The reviewed status records a
model semantic fidelity review, not human certification or a change to official
Italian answers. Structural and heuristic checks alone never mark text reviewed.

Translation rules: retain the source claim even when its exam answer is FALSO;
preserve negations, exceptions, numeric limits, units, vehicle/sign labels,
time periods and legal qualifiers. Do not insert explanations or correct a false
statement into a true rule. Distinguish parking (`sosta`) from temporary stopping
(`fermata`), and own-account transport from transport for hire or reward. Preserve
technical abbreviations where appropriate and translate the surrounding text.
See the earlier A/B review in `../reviews/ab-translation-review.md` for common pitfalls.

## Latin American Spanish

`es-419/NNN.csv` contains `id,text,origin,review_status`, keyed by the same
normalized Italian text IDs. All translations are generated by GPT-6.1 Terra
sub-agents and start as `draft`. Separate Terra reviewers read every Italian/Spanish
pair, fix errors, and mark the completed batch `reviewed`. English/Chinese review
evidence does not certify Spanish. Neutral Latin American terminology should retain the Italian regulatory
context; do not substitute another country's laws or fix a false quiz statement.

```sh
python3 scripts/spanish_translations.py --prepare
python3 scripts/spanish_translations.py --require-complete --require-reviewed
```

The generated `tasks/es-419/NNN.csv` files contain the Italian source for each
batch. They are ignored and can be regenerated from the tracked bank CSV files.
The optional database's strict translation gate covers all three target languages;
the strict review gate also rejects Spanish drafts. Missing translations remain
NULL and are counted as missing, never filled with another language.

Spanish review evidence is stored in `reviews/spanish-review/NNN.json`. Each
report binds the entire final CSV and its actual Italian sources to SHA-256
fingerprints, names the Terra reviewer agent and date, and records before/after
wording and specific reasons for every correction. `baseline.json` records the
original draft hashes. The validator reconstructs each original draft from the
reviewed rows and correction history, so verification does not depend on a local
temporary directory or access to earlier Git history. Changes to either language
or the correction history invalidate review evidence.

The 2026-11-19 second pass re-read every Italian/Spanish row with Claude Haiku 5.5
subagents. Its evidence records `reviewer_model` `claude-haiku-5-5`; the earlier
GPT-6.1 Terra pass is kept under `previous_review`. `BACKENDS` in
`scripts/worker_models.py` lists the accepted author and reviewer models.

Reviewers use `spanish_review.record_review` only after comparing every row. The
helper records evidence; it does not perform semantic review. Unresolved batches
remain draft. This is model review of translation fidelity, not human certification
or verification of the truth of Italian quiz statements.
